## 1. Ringkasan Eksekutif

Bisnis ini berfokus pada penjualan sistem kasir (Point of Sale/POS)
dengan merek sendiri, yang dapat dibundel dengan perangkat kasir seperti
printer thermal, cash drawer, barcode scanner, dan tablet atau komputer.

Dengan modal awal Rp5 juta, strategi yang paling aman adalah:

1.  Memulai dari satu segmen, yaitu retail kecil.
2.  Mengembangkan satu produk POS yang dapat berjalan offline.
3.  Membeli satu set hardware untuk demo dan pengujian.
4.  Mengintegrasikan QRIS dinamis melalui satu payment gateway.
5.  Menguji produk pada 1--2 toko pilot.
6.  Menjual berdasarkan pesanan (*build-to-order*), bukan menumpuk stok.

**Target awal:** membuktikan bahwa produk benar-benar menyelesaikan
masalah toko dan ada pelanggan yang bersedia membayar.

Produk tidak perlu langsung memiliki seluruh fitur retail, restoran, dan
laundry. Stabilitas transaksi, data, pembayaran, dan perangkat jauh
lebih penting pada tahap awal.

## 5. Produk dan Arsitektur Teknis

### 5.1 Prinsip produk

Buat satu produk POS inti dengan dua jenis terminal:

-   Desktop POS.
-   Android Tablet POS.

Jangan membuat dua aplikasi terpisah jika alur bisnis dan fitur intinya
sama.

### 5.2 Arsitektur yang disarankan

``` text
Desktop POS / Android Tablet POS
        |
        | PWA / HTTP lokal
        v
Go Local Hub
  - API lokal
  - autentikasi
  - printer agent
  - sinkronisasi
        |
        v
SQLite
  - transaksi lokal
  - produk dan stok
  - pembayaran
  - audit lokal

        |
        | Sinkronisasi saat online
        v
Cloud Backend
  - backup
  - lisensi
  - dashboard
  - QRIS API
  - webhook
  - rekonsiliasi
```

### 5.3 Teknologi

  Area              Rekomendasi
  ----------------- -------------------------------
  Frontend          Next.js + TypeScript
  Terminal          PWA
  Local Hub         Go
  Database lokal    SQLite
  Cloud database    PostgreSQL
  Sinkronisasi      Transactional outbox
  Printer           ESC/POS
  Barcode scanner   USB HID
  QRIS              Payment gateway API
  Backup            Backup lokal + cloud opsional

### 5.4 Model offline-first

-   Transaksi lokal disimpan ke SQLite terlebih dahulu.
-   Commit transaksi harus berhasil sebelum struk dicetak.
-   Sinkronisasi ke cloud berjalan secara asynchronous.
-   Gunakan transactional outbox agar event tidak hilang ketika koneksi
    putus.
-   Setiap outlet memiliki database lokal sendiri.
-   Cloud mengonsolidasikan data dari setiap outlet.

**Batasan offline:** jika PC Local Hub atau router mati, terminal lain
tidak otomatis dapat bertransaksi. Sistem harus memiliki prosedur
pemulihan dan backup. Jangan menjanjikan offline tanpa batas.

## 7. Integrasi Hardware

### 7.1 Printer thermal

-   Gunakan ESC/POS.
-   Prioritaskan printer 80mm USB dan LAN.
-   Buat Go Print Agent untuk mengakses printer dari Local Hub.
-   Uji cetak teks, logo, barcode, panjang struk, dan karakter
    Indonesia.
-   Uji kondisi printer mati, kertas habis, dan koneksi terputus.

### 7.2 Cash drawer

-   Hubungkan cash drawer ke port RJ11 printer.
-   Gunakan perintah drawer-kick setelah pembayaran tunai selesai.
-   Jangan membuka drawer hanya karena halaman checkout dibuka.
-   Catat aktivitas pembukaan drawer jika diperlukan.

### 7.3 Barcode scanner

-   Mulai dari USB HID agar scanner terbaca sebagai input keyboard.
-   Uji barcode produk, barcode tidak dikenal, dan input berulang.
-   Pastikan fokus input kasir tidak mengganggu penggunaan scanner.

### 7.4 Tablet

-   Gunakan PWA melalui browser.
-   Tablet terhubung ke Local Hub melalui jaringan lokal.
-   Uji ukuran layar, orientasi, keyboard, dan koneksi ulang.

## 8. Integrasi QRIS

### 8.1 Provider untuk discovery

  Provider   Integrasi yang perlu dievaluasi
  ---------- ---------------------------------------------------
  Midtrans   QRIS melalui Charge API dan notifikasi pembayaran
  Xendit     QRIS melalui QR Codes API
  Duitku     Payment API dan HTTP callback

Mulai dengan satu provider untuk proof of concept. Buat abstraksi
provider agar integrasi lain dapat ditambahkan tanpa mengubah alur POS.

Dokumentasi resmi: - Midtrans: https://docs.midtrans.com/ - Xendit:
https://docs.xendit.co/ - Duitku: https://docs.duitku.com/

Verifikasi kembali ketersediaan produk QRIS, persyaratan onboarding,
biaya, settlement, dan ketentuan merchant saat pendaftaran.

### 8.2 Alur pembayaran

``` text
Kasir checkout
    |
    v
Transaksi disimpan lokal
status = pending_payment
    |
    v
Cloud Backend meminta QRIS
ke payment gateway
    |
    v
QR ditampilkan ke pelanggan
    |
    v
Pelanggan membayar
    |
    v
Provider mengirim webhook
    |
    v
Backend memverifikasi:
- signature
- nominal
- merchant
- transaction ID
- status
    |
    v
Status pembayaran terverifikasi
    |
    v
Local Hub menerima status
dan menyelesaikan transaksi
```

### 8.3 Aturan keamanan dan keandalan

-   Gunakan idempotency agar webhook berulang tidak menggandakan
    pembayaran.
-   QR memiliki masa berlaku.
-   Verifikasi signature webhook.
-   Cocokkan nominal, merchant, dan ID transaksi.
-   Sediakan pengecekan status melalui API jika webhook terlambat.
-   API secret hanya disimpan di backend.
-   Screenshot bukti transfer tidak menjadi bukti pembayaran otomatis.
-   Jika terminal kehilangan koneksi, status tetap `pending` sampai bisa
    diverifikasi.
-   Sediakan rekonsiliasi transaksi POS dengan laporan provider.

### 8.4 Aturan offline

-   Tunai tetap dapat digunakan saat internet mati.
-   QRIS dinamis memerlukan koneksi untuk pembuatan dan verifikasi
    pembayaran.
-   QRIS statis dapat menjadi fallback, tetapi konfirmasi manual harus
    dicatat sebagai pembayaran manual dan tidak boleh disamakan dengan
    webhook terverifikasi.
-   Jangan menganggap transaksi QRIS lunas hanya berdasarkan pengakuan
    pelanggan atau screenshot.

### 8.5 MDR dan biaya provider

MDR QRIS mengikuti ketentuan Bank Indonesia dan kategori merchant.
Periksa ketentuan terbaru ketika onboarding karena tarif dan aturan
dapat berubah.

Biaya provider, settlement, refund, dan biaya layanan lain harus
dikonfirmasi langsung melalui penawaran resmi masing-masing provider.

Model yang disarankan: merchant memiliki akun payment gateway sendiri
dan dana masuk langsung ke merchant. POS hanya mengintegrasikan proses
pembayaran.

## 11. Kriteria Produk Siap Dijual

-   Transaksi tidak hilang setelah listrik mati atau aplikasi restart.
-   Backup dapat dipulihkan.
-   Printer bisa mencetak struk tanpa menggandakan transaksi.
-   Scanner dapat membaca barcode produk.
-   Cash drawer terbuka sesuai metode pembayaran.
-   QRIS hanya dianggap lunas setelah terverifikasi.
-   Laporan penjualan sesuai dengan transaksi.
-   Lisensi tidak menghilangkan akses pelanggan ke data miliknya.
-   Ada panduan instalasi dan pemulihan.
-   Ada prosedur support dan garansi hardware.

## 12. Strategi Mendapatkan Pelanggan

1.  Datangi 10 toko yang sesuai target.
2.  Tunjukkan demo menggunakan hardware.
3.  Tawarkan pilot 14--30 hari dengan kesepakatan yang jelas.
4.  Catat masalah dan permintaan fitur yang benar-benar muncul.
5.  Minta izin menggunakan testimoni setelah pilot berhasil.
6.  Tawarkan paket hardware berdasarkan uang muka.
7.  Setelah memiliki 3--5 pelanggan, mulai mencari reseller perangkat
    atau teknisi lokal.

### Aturan pengadaan

-   Jangan membeli hardware untuk persediaan.
-   Minta uang muka sebelum memesan perangkat pelanggan.
-   Periksa garansi dan kebijakan DOA.
-   Lakukan QC sebelum instalasi.
-   Pisahkan garansi software dan garansi hardware.
